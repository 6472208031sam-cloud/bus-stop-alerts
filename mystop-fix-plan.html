Bug 1: ntfy Missing "Got Off" on St Cecilia PM

What Domi saw

PM route, My Stop set. On-screen alert correctly showed "Got off at Stop I: Mia." But the ntfy message sent was the generic 🚌 [X##] at Stop I (1): Mia. instead of 📱 [X##] got off at Stop I (1): Mia.

Root cause

The native background service (not the web page) sent the ntfy. It detects My Stop by parsing the label string:

stop.label = "Stop I (1): Mia"
  → strip "Stop " → "I (1): Mia"
  → strip after ":" → "I (1)"
  → compare to myStopPm = "I"
  → "I" ≠ "I (1)" → NOT detected as My Stop ✗

The web page uses structured fields (stop.letter === "I") so it displayed correctly on-screen. Only the native service got it wrong.

The Bus app already has this fix (strips the (N) suffix). St Cecilia is missing it in both Android and iOS.

Feature 2: Auto-Stop Ride on "Got Off" (PM only)

What Domi asked

When My Stop is reached on PM ("got off"), that phone's journey is done → stop tracking automatically.

Why PM only

On AM, "waiting at" means the kid is at the stop about to board — the journey continues. Stopping there would kill tracking before the bus arrives. On PM, "got off" means the kid left the bus — journey over.

Implementation

LayerChangeApplies to
Web appIn triggerArrival(), after sending "got off" ntfy → send 📱 [X##] off bus. Tracking stopped. → call stopTracking() (this also stops the native service via NativeBridge.stopRide())Bus + StC
Android nativeIn onArrival(), after sending "got off" ntfy → send 📱 [X##] off bus. Tracking stopped. → stop the foreground serviceBus + StC
iOS nativeIn LocationTracker, after sending "got off" ntfy → send 📱 [X##] off bus. Tracking stopped. → stop location updatesBus + StC

Edge cases

ScenarioBehavior
My Stop is mid-route (not final)Stops tracking for this phone; bus continues for others. Correct — this phone's rider got off.
Only phone on bus gets off earlyCritical: follower must know tracking ended. After "got off" ntfy, send 📱 [X##] off bus. Tracking stopped. so the follower doesn't just go silent.
User taps Test button on My StopWould also auto-stop. Acceptable for test fidelity.
User wants to continue after getting offTap Start to resume tracking manually.
AM "waiting at"No auto-stop (journey continues).
My Stop = "auto" (not set)No change — normal arrival flow.

Does Bus App Need This?

Bug 1: No — Bus native already strips (N).
Feature 2: Yes — Bus has the same "got off" PM flow. For consistency, both apps should auto-stop.
