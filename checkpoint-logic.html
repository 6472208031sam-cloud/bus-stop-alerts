On-Bus Detection Logic (Review Only — Not in App)

Concept: Invisible checkpoint 150m after each stop along the route. When the phone crosses it after that stop was reached → user is on the bus.

1. Checkpoint Data

// One per stop (except final). 15 PM + 12 AM.
var PM_CHECKPOINTS = [
  { after: "S",  heading_to: "0",  lat: 43.49320, lng: -79.69245 },
  { after: "0",  heading_to: "01", lat: 43.49136, lng: -79.69309 },
  { after: "01", heading_to: "02", lat: 43.48738, lng: -79.69952 },
  // ... etc for all stops
];

2. Detection (runs on each GPS fix)

// cps = checkpoints for current mode (AM or PM)
for (var i = 0; i < cps.length; i++) {
  var cp = cps[i];
  var afterStop = stops[cp.after_idx];

  // Only check if that stop was already reached,
  // and we haven't fired for it yet
  if (afterStop.reached && !onBusState[cp.after_idx]) {

    var d = distanceMeters(lat, lng, cp.lat, cp.lng);

    if (d <= 50 && accuracy <= 100) {
      onBusState[cp.after_idx] = true;

      var next = stops[cp.after_idx + 1];
      sendNtfy("📱 " + deviceId +
        " on bus, heading to " + stopLabel(next) + ".");
    }
  }
}

3. State

var onBusState = {};  // stopIdx → true once checkpoint crossed
// Reset on ride start / reset progress
Why 150m? Far enough that GPS drift at the stop won't trigger it, close enough to fire soon after the bus pulls away.
Why 50m radius? Matches existing arrival detection tolerance.
