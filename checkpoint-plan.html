On-Bus Detection — Detailed Plan AWAITING APPROVAL

1. Goal

Detect when a waiting rider's phone transitions to "on the bus and moving toward the next stop" on the AM route only, and notify followers via ntfy.

Why AM only: AM is pickup (waiting → boarding). PM is drop-off — the "got off" message already covers it.

2. Checkpoint Data

12 invisible checkpoints, one 150m along the route after each AM stop (except the final stop 13).

#After StopHeading ToDistancePurpose
1Stop 1Stop 2~150mDetect boarding at Stop 1
2Stop 2Stop 3~150mDetect boarding at Stop 2
...............
12Stop 12Stop 13~150mDetect boarding at Stop 12

Coordinates calculated once from AM route geometry (428 points). Stored as a static AM_CHECKPOINTS array in index.html. Never displayed as stops.

3. Detection Logic

Runs inside onPosition() on every GPS fix, after the existing arrival check:

var cps = AM_CHECKPOINTS;  // AM only
for (var i = 0; i < cps.length; i++) {
  var cp = cps[i];
  var afterStop = stops[cp.after_idx];

  // Gate 1: the "after" stop must already be reached
  // Gate 2: haven't fired for this stop yet
  if (afterStop && afterStop.reached && !onBusState[cp.after_idx]) {

    var d = distanceMeters(lat, lng, cp.lat, cp.lng);

    // Gate 3: within 50m of checkpoint
    // Gate 4: GPS accuracy ≤ 100m (no drift false-positives)
    if (d <= 50 && accuracy <= 100) {
      onBusState[cp.after_idx] = true;

      var next = stops[cp.after_idx + 1];
      var msg = "📱 " + deviceId +
        " on bus, heading to Stop " + next.number +
        ": " + next.name + ".";
      sendNtfy(msg);
      logEvent('STOP', 'On-bus: ' + msg);
    }
  }
}

5. ntfy Message Format

📱 [A82] on bus, heading to Stop 6: Crimson Oak.

Follows existing device-ID convention. Follower already parses 📱 [X##] prefix — no follower changes needed for basic display.

6. Edge Cases

ScenarioBehavior
User doesn't boardPhone never crosses checkpoint → no false "on bus"
Bus skips the stopStop never marked reached → checkpoint never checked
GPS drift at stop150m distance + 100m accuracy gate prevents false trigger
User walks 150m along routeWould trigger — acceptable (they're heading the right way)
Mid-route ride startSnap-forward marks earlier stops reached; checkpoints for those stops are skipped (already past them)
Test button tappedSimulates arrival but phone doesn't move → checkpoint won't fire (correct)
